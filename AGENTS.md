# Release writing

Standing correction from Himan, October 29, 2026.

- Public release pages serve everyone downloading the game. Preserve the useful
  structure and tone of Himan's v0.1.0 release: overview, requirements, testing
  status, installation, controls/limitations, test checklist and source download.
- Read the actual previous release before writing an update. Preserve established
  instructions where they still apply; change only what the new version requires.
- Use the established title format: game name, version and build status. Do not
  rename or brand a release around one tester, device-specific report or minor fix.
- Summarize routine fixes briefly in the changes section. A specific report must
  not take over the introduction, audience or testing instructions for the release.
- Keep reporter names, troubleshooting narratives, helper flags, implementation
  details and extended validation evidence in developer notes or the relevant
  Discord discussion. Replying to testers requires separate user authorization.
- Keep public compatibility claims accurate and concise. Record pending device
  retests in the status table without turning the page into a diagnostic report.
- Review the complete page as a new downloader: it should explain how to install
  and test the game without requiring knowledge of the latest Discord exchange.
- Himan rejected the initial v0.1.1 title and report-centered notes. They are not
  an accepted template. The corrected notes are in `docs/releases/ddd-v0.1.1.md`.
